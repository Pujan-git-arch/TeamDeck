# Database Models

This document describes the SQLAlchemy models in `backend/app/models/`. It is a schema reference for backend and frontend developers; the Python model files remain the source of truth.

## Conventions

- PostgreSQL is the target database.
- All model identifiers are UUIDs generated by the application unless noted otherwise.
- Timestamp columns use timezone-aware `DateTime` values.
- `created_at` and most `joined_at` values default to `CURRENT_TIMESTAMP` in the database.
- Nullable foreign keys are represented as optional UUIDs and use `ON DELETE SET NULL` or `ON DELETE CASCADE`, as listed below.
- `updated_at` is present on mutable entities. `Project`, `Task`, and `Comment` define a SQLAlchemy `onupdate` expression; `User` currently has only a server default.

## Entity Overview

| Model | Table | Purpose |
| --- | --- | --- |
| `User` | `users` | Account, access role, approval state, and optional avatar. |
| `Project` | `projects` | A workspace owned by one user. |
| `ProjectMember` | `project_members` | Composite-key membership of a user in a project. |
| `Task` | `tasks` | Work item belonging to a project, with optional assignee. |
| `Comment` | `comments` | A user's comment on a task. |
| `Attachment` | `attachments` | Uploaded file associated with a user and optionally a project, task, or comment. |
| `TaskAttachment` | `task_attachments` | Composite-key link between tasks and attachments. |
| `Activity` | `activities` | Project activity event with a flexible JSON payload. |
| `Notification` | `notifications` | Message addressed to a user, optionally representing an entity event. |

## Enum Values

| Enum | Values |
| --- | --- |
| `account_status_enum` | `pending`, `active`, `rejected`, `suspended` |
| `user_role_enum` | `super_admin`, `admin`, `manager`, `developer`, `designer`, `hr`, `qa_tester`, `viewer` |
| `task_status_enum` | `todo`, `in_progress`, `review`, `done` |
| `task_priority_enum` | `low`, `medium`, `high`, `urgent` |
| `attachment_kind_enum` | `avatar`, `project_cover`, `task_attachment`, `comment_attachment` |

## Relationship Map

```text
User 1---* Project                  (owner)
User *---* Project                  (through ProjectMember)
Project 1---* Task
User 1---* Task                     (assignee, creator)
Task 1---* Comment
User 1---* Comment                   (author)
User 1---* Attachment                (uploader)
Task *---* Attachment                (through TaskAttachment)
Project 1---* Activity
User 1---* Activity                  (actor)
User 1---* Notification              (recipient)
```

`Activity.entity_id` and `Notification.entity_id` intentionally use application-level polymorphic references. They identify an entity together with `entity_type`, but do not enforce referential integrity through a foreign key.
