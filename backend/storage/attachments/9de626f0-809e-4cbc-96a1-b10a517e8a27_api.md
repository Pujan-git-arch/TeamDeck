# API Overview

This document summarizes the backend API surface exposed by the FastAPI application in `backend/app/main.py` and the route modules in `backend/app/routers/`.

## Base Configuration

- Application name: `TeamDeck API`
- API framework: FastAPI
- Session handling: SQLAlchemy session factory via `get_db()`
- Authentication: JWT bearer token flow using `OAuth2PasswordBearer`

## Included Routers

| Router | Prefix | Purpose |
| --- | --- | --- |
| `auth` | `/auth` | Login and registration |
| `users` | `/users` | User profile and admin user management |
| `projects` | `/projects` | Project lifecycle and access |
| `project_members` | `/projects/{project_id}/members` | Membership management |
| `project_tasks_router` | `/projects/{project_id}/tasks` | Project-scoped task creation and listing |
| `tasks_router` | `/tasks` | Task-scoped read, update, delete, and assigned-task lookup |
| `task_comments_router` | `/tasks/{task_id}/comments` | Task-scoped comment creation and listing |
| `comments_router` | `/comments` | Comment-scoped read, update, and delete |
| `notifications` | `/notifications` | Personal notification management |
| `activities` | `/activities` | Project and system activity records |
| `project_attachments_router` | `/projects/{project_id}/attachments` | Project attachment listing |
| `task_attachments_files_router` | `/tasks/{task_id}/attachments/files` | Task attachment listing |
| `comment_attachments_router` | `/comments/{comment_id}/attachments` | Comment attachment listing |
| `attachments_router` | `/attachments` | Attachment retrieval, upload, and deletion |

## Authentication and Authorization

The authentication flow starts in `backend/app/dependencies/auth.py`:

- `get_current_user()` validates the JWT and loads the active user.
- `require_admin()` restricts endpoints to `admin` or `super_admin` users.
- `require_manager()` restricts endpoints to `manager` users.
- Project-specific access is validated by dependencies in `backend/app/dependencies/project.py`.

## Notes

- The app is organized by feature modules and route groups.
- Tasks, comments, and attachment operations are implemented and mounted through multiple scoped routers from their respective modules.
- Authorization is enforced mostly through dependency functions rather than duplicated checks inside each route.
